## B-VER-02 · 切换验证四项检查

**使用时机**：部署或切换动作执行完之后、进入验收（VER-05）之前。
**前置**：已知本次部署的唯一版本标识（构建号 / 镜像 digest / commit 短哈希）。
**一键版**：`kit/verify-switch.sh`（覆盖范围见正文 VER-02 判定标准；LB 后端表必须人工）。

```checklist
[ ] VER-02.1  服务管理器认为它在运行
              systemd: is-active 输出 active ｜ K8s: Pod Running 且 READY 分子=分母
[ ] VER-02.2  正在响应的实例，版本对得上
              [ ] 用不可变标识（digest/构建号/哈希），不用 tag
              [ ] 查到的标识与本次部署逐字符相等
              [ ] Web 交付：带 cache-busting 查一次 + 直连源站查一次，两次都对上
[ ] VER-02.3  旧实例已经清干净
              [ ] 无「父进程为 1 且早于本次部署」的进程残留
              [ ] 编排环境：旧版本副本无一处于 Running
              [ ] 负载均衡：运行时后端表（不是配置文件）中无旧实例地址
[ ] VER-02.4  它真的干过活
              [ ] 打了一次带唯一标识的真实业务请求
              [ ] 该标识在新实例日志中 grep 命中
[ ] 采样覆盖  多节点分发场景：采样覆盖全部节点（或每分组有样本），
              且横跨至少一个完整下发周期
[ ] 判定输出  四项判定标量已粘贴进过程资产，VERDICT=SWITCHED 才进入 VER-05
```

**打分规则**：全部为「是」→ 切换完成。任一为「否」或「没测」→ 按未完成处理，
修复后**重跑全部四项**（不是只补挂掉的那条——见正文 ROL-04.3 回边规则）。
