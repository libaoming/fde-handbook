# 第 0 部 · 怎么用这本手册

这是一本供查阅的手册，不是从头读到尾的书。用法只有三条。

## 两个入口

| 你的问题 | 入口 |
|---|---|
| 「我在交付的哪一步，该做什么」 | **主线**：ROL-04 全景图 → 按阶段进第 2 部对应节 |
| 「我遇到了这个症状，去哪查」 | **速查**：附录 A 按症状索引，每条指向正文节 |

第 1 部（这份工作）定义角色与交付物；第 3 部（验证纪律）不属于任何单一阶段，
贯穿每个关口。头一次翻这本手册，读 ROL-04 一节就够上手。

## 编号体系

任何检查项、速查条目都有一个不漂移的编号，供评审、工单、聊天引用：

```
阶段   ENG 承接 · SUR 勘察 · BLD 搭建 · DEP 上线 · VER 签收 · HND 移交
节     VER-02        检查项  VER-02.3        速查  FX-SVC-01（附录 A）
横切   ROL（角色）· DIS（验证纪律）· 附录 B（检查表）· 附录 C（模板）
```

## 案例档位（读者必须知道哪些是构造的）

正文案例分三档，**每处强制标注**：

| 档 | 标注 | 你能拿它做什么 |
|---|---|---|
| 公开事故复盘 | 附原始 postmortem 链接与核实日期 | 可自行查证、可引用 |
| 合成示例 | 显式标「合成示例（教学场景，非真实事故）」，不含伪造的时间戳/PID/哈希/日志原文 | 理解机理，不当事实引用 |
| 引证（第三方声明） | 附来源与**不可外推边界** | 连同边界一起引用，不得越界外推 |

区别不在案例谁写的，在读者知不知道它是构造的。发现分档冒充，请提 issue——
那是这本手册的红线。

## 一条贯穿全书的缺省

**拿不准时按更坏的情况处理**：没测 = 未通过，没写 = 没做，沉默 = 未知。
每张判定表都配这条兜底；理由见 DIS-01/DIS-02，业界出处（PagerDuty
"Always Assume The Worst" 的类比借用）见 VER-02 判定标准。

另一条排版约定：**引文内的着重（加粗）均为本手册所加**，原文无强调标记。
