# DIS-04 · 事故台账：失败怎么进流程才算被吸取

**目的**　给「吸取教训」一个可判定的定义：失败被吸取 = 它的证伪过程被**当时**记下，
且行动项**变成了某个检查表条目或闸门**。达不到这两条的复盘，无论会开得多深刻，
留下的只是情绪记录。

**前置条件**
- 无。本节从第一次失败开始适用——而第一次失败通常在勘察阶段就会到来。

---

## 规程

### DIS-04.1　记什么：书面、结构化、有根因

行业对这个体裁有成熟定义，Google SRE："A postmortem is a written record of an
incident, its impact, the actions taken to mitigate or resolve it, the root cause(s),
and the follow-up actions to prevent the incident from recurring."
——五要素：事故、影响、处置、根因、防复发行动。**少了最后一项的记录是新闻，不是台账。**

### DIS-04.2　何时记：当轮，不指望事后对账

证据在事发当时最全，之后单调衰减：session 日志会灭失、运维动作不产生 commit、
聊天记录会被淹没。**台账条目在事发当轮写下**，至迟当天——
记不清的字段标 `⚠️ 待复核`，禁止事后补脑（溯源律在台账上的形态）。

### DIS-04.3　条目模板：误判链是主体

台账条目六段，其中**误判链是主体**——你先以为是什么、为什么那条路错了，
这正是翻车律要求写全的部分，也是条目对下一个读者的全部价值：

```checklist
[ ] 现象：观察到了什么（可粘贴的输出，不是转述）
[ ] 误判链：先怀疑了什么 → 什么证据证伪了它（逐跳记录）
[ ] 根因：最终确认的机理，附确认它的那条证据
[ ] 处置：当场做了什么，哪些改动事后要回退（FX-NET-01 的教训）
[ ] 行动项：防复发动作，每项有 owner 与期限
[ ] 闸门化：行动项落到了哪条检查表/哪个脚本/哪道闸门（见 DIS-04.4）
```

### DIS-04.4　闭环判据：行动项要么闸门化，要么显式关闭

行动项只有两个合法终态：

1. **闸门化**——变成检查表条目、验收判据、lint 规则或验证脚本的一条断言。
   参照 Replit 对自家数据 agent 的描述："The data agent checks whether a number can
   be trusted using row counts, metric definitions, and **the failure modes that have
   burned us before**; it returns the evidence with the answer."——
   **闸门的内容来自烧过自己的事故，不来自想象**；
2. **显式关闭**——写明为什么不做（成本、不再适用），签名留档。

第三种状态「挂着」不合法：挂了三个月的行动项与没有行动项，对下一次事故等效。
公开案例里这个等效性的代价见 PM-09（GitLab 2017）：备份失败的告警邮件被静默丢弃
无人处置——**已知的失败模式没有闸门化，于是它按原样再次发生。**

### DIS-04.5　无责边界

"Blameless postmortems are a tenet of SRE culture."——台账记录机理与证伪过程，
不记录追责。但注意语境边界：**无责是组织内文化，不豁免交付方对客户的合同责任**；
对客户的事故通报是另一份文档，口径由 ROL-02 的商务接口把关，两者不要混写。

## 常见误判

**「复盘会开过了，教训吸取了」**
会议产生共识，不产生闸门。散会时如果没有 DIS-04.3 的条目和 DIS-04.4 的终态计划，
这次失败的下一次出现只是时间问题。

**「记了台账 = 吸取了教训」**
台账是原料。判据在 DIS-04.4：行动项闸门化率——
翻开你的台账数一数有几条行动项处于「挂着」态，那就是你的复发敞口。

**「小事故不值得记」**
闸门的内容来自事故（DIS-04.4），小事故是最便宜的闸门原料——
它用最小的代价暴露同一类机理。等大事故来教学，学费不一样。

**「先追清楚是谁的责任」**
追责与找根因用的是两套问题，混在一起两个都得不到：
人在防御姿态下不会交出误判链，而误判链正是条目的主体（DIS-04.3）。

## 判定标准

```checklist
[ ] 每次事故当轮有条目，六段齐全，误判链逐跳可读
[ ] 无「挂着」态行动项：全部处于闸门化或显式关闭
[ ] 闸门化的行动项能指到具体检查表条目/脚本断言（编号可引用）
[ ] 对客户的通报与内部台账分开成文
```

保守缺省：一条行动项拿不准要不要做 → 按显式关闭走流程（写下为什么），
而不是留在挂着态——**被写下来的「不做」可以被推翻，挂着的「再说」只会过期。**
