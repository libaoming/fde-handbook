# ROL-04 · 全景图：六阶段与关口

**目的**　给整本手册的主线入口一张图：交付分哪六个阶段、阶段之间的关口各要什么。
读完本节你应该能随时回答三个问题：**我在哪个阶段；上个关口的判定输出在哪；
下个关口需要什么。**——答不出其中任何一个，你就不在你以为的阶段里。

**前置条件**
- 无。本节与 ROL-01 同为全书入口。

> "Dev versus Delta" 原文——文中描述工作内容用的是活动词
> （scoping、monitoring、debugging、deploying、configuring），

## 规程

### ROL-04.1　六阶段总表

```
ENG 承接 → SUR 勘察 → BLD 搭建 → DEP 上线 → VER 签收 → HND 移交
                └──────── 第 3 部 · 验证纪律（DIS）贯穿全程 ────────┘
```

| 阶段 | 核心问题 | 进入条件 | 退出条件（关口） | 已成稿节 |
|---|---|---|---|---|
| **ENG 承接** | 这活能不能接？红线在哪？成功标准怎么定义？ | 有明确的对手方与诉求 | 成功标准与红线双方书面认可；交付物清单（ROL-03）建立 | —（未成稿） |
| **SUR 勘察** | 现场环境、约束、依赖、不在工程域里的阻塞项各是什么？ | ENG 关口已过 | 环境清单、依赖清单、阻塞项登记表（ROL-02.4）齐 | —（未成稿） |
| **BLD 搭建** | 最小可用链路怎么搭？换链路丢了什么能力？ | SUR 关口已过 | 链路在客户环境跑通，丢失能力清单确认 | BLD-03、BLD-04 |
| **DEP 上线** | 怎么部署、切换、灰度？回滚预案是什么？ | BLD 关口已过 | 切换动作执行完，回滚预案演练过 | —（未成稿） |
| **VER 签收** | 什么算做完了？证据链怎么留？ | DEP 关口已过 | 全部签收判据通过并留档（**本手册的重心**） | VER-02、VER-03、VER-04 |
| **HND 移交** | 运维、监控、责任怎么交出去？ | VER 关口已过 | 客户按移交资产独立运行过（ROL-03.1） | —（未成稿） |

### ROL-04.2　关口规则

阶段之间的过渡必须有**可粘贴的判定输出**，不是一句「我觉得可以进入下一阶段了」：

1. 上一阶段的退出条件逐项核对，每项有可观察的证据（判定标量的形态见 DIS-02）；
2. 判定输出粘进过程资产（ROL-03.1 第四类），关口日期与输出一起留档；
3. **退出条件不满足就进入下一阶段 = 把缺口带进定义更模糊的地方**——
   ENG 没定成功标准，VER 就没有判据可执行；SUR 没登记阻塞项，DEP 就会撞上
   不产生任何技术信号的停摆（ROL-02 案例框那种形态）。缺口不会消失，只会改名。

### ROL-04.3　回环：线性图只是主干

六阶段按顺序画，但三条回边是常态而非例外：

| 回边 | 触发 | 动作 |
|---|---|---|
| VER → BLD/DEP | 签收判据不过 | 修复后**重跑全部相关判据**，不是只补挂掉的那条（回滚也是一次切换，见 FX-SVC-01 Rollback） |
| SUR → ENG | 勘察发现红线（做不了、不该做、成本远超预估） | 回 ENG 重议范围或退出——**勘察的价值一半在于此**，别把它当走过场 |
| HND → ENG | 发现无人可交（客户侧没有承接角色） | 回 ENG 的干系人表补角色；这说明 ENG 关口当时就漏了 |
| **不存在的回边** | 「跳过 SUR 直接 BLD，出问题再回来勘察」 | 这不是回边，是把 SUR 的成本换成 DEP/VER 的事故——一笔代价大得多的置换 |

### ROL-04.4　验证纪律不是一个阶段

第 3 部（DIS-01~04）不出现在六阶段序列里，因为它**贯穿每个关口**：
每个关口的判定输出都用 DIS-02 的形态（判定标量，不是三段描述），
每份证据按 DIS-01 分级，用 AI 助手干活的每一步受 DIS-03 约束。
**VER 是集中签收的阶段，不是验证唯一发生的阶段**——把验证推迟到 VER 才开始做，
等于让缺陷带息滚存四个阶段。

## 常见误判

**「阶段是线性的，走完一个就不回头」**
回边是常态（ROL-04.3）。区别专业与否的不是「有没有回去」，
而是回去时**走不走关口**——带着判定输出回去重议，和「悄悄回去改改」是两回事。

**「验证是 VER 阶段的事」**
VER 只是集中签收（ROL-04.4）。每个阶段的退出条件本身就是验证；
第 3 部的纪律从 ENG 第一天就生效。

**「跳过 ENG/SUR 能省时间」**
省下的是**定义问题的时间**，代价是后面每个阶段都在一个没有成功标准、
没有环境清单的空间里工作——每个判断都要现场重新发明依据。
本手册对此不给弹性：ENG/SUR 的退出条件没有「可选」标记。

**「框架是标准的，照着走就有背书」**
没有背书，见开头的框架声明。框架给你的是挂点和检查项，
「走了流程」本身不构成任何证据——证据只来自每个关口的判定输出。

## 判定标准

任一时刻抽查，三问自检：

```checklist
[ ] 我能说出当前处于哪个阶段（以及依据：上个关口的判定输出在哪份过程资产里）
[ ] 我能列出下个关口的退出条件，且每条知道将用什么证据满足
[ ] 当前阶段之外的活动（提前搭链路、提前谈移交）已显式标记为预研，不冒充关口已过
```

三问全过才算「在框架内」。第三问防的是最隐蔽的漂移：
提前做下阶段的事不是错，**把「提前做了」当成「关口过了」才是**。
