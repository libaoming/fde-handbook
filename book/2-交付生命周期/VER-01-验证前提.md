# VER-01 · 验证前提：先确认你的验证手段可信

**目的**　在相信任何绿灯之前，先审计绿灯本身。三个问题：你的观测手段与被观测系统
**共不共享依赖**；你的探针测的**是不是你以为的东西**；「一切安静」到底是证据还是盲区。
验证手段不可信时，后续所有验证（VER-02~05）的结论都是空转。

**前置条件**
- 知道本次交付用什么看系统：监控、告警、日志、健康检查各在哪、走什么链路（SUR-01.1 的产出）

---

## 规程

### VER-01.1　独立性核查：故障发生时，报信的通道还活着吗

列出验证链路（监控采集、告警投递、日志存储、状态页）的依赖，
与被验证系统的依赖**做交集**。交集里的每一项都是一个盲区制造者：
它故障时，验证手段和故障一起消失，你得到的不是告警，是安静。

两个公开事故把这个形态写得很清楚：

- Roblox 2021（2021-10-28～31，持续三天余的全站故障）："Critical monitoring systems that would have provided
  better visibility into the cause of the outage relied on affected systems, such as
  Consul. This combination severely hampered the triage process."
- AWS S3 2017：连状态页都受灾——"we were unable to update the individual services'
  status on the AWS Service Health Dashboard (SHD) because of a dependency the SHD
  administration console has on Amazon S3."

**判据**：假设被验证系统整体宕机，逐项问「这个观测通道还工作吗」。
答案为否的通道，**它的『安静』永远不能当证据用**——在判定表里把它标出来。

### VER-01.2　探针语义核查：它测的是什么

每个健康检查/探针写一行「它实际断言了什么」：

| 探针 | 它实际断言 | 它**不能**断言 |
|---|---|---|
| 端口存活 | 有进程在监听 | 业务逻辑可用 |
| HTTP 200 | 有东西返回了 200 | 返回内容正确（PM-03 形态：200 + 空结果） |
| 进程存在 | 进程在 | 接活的是新版本（VER-02 的全部理由） |
| 业务事件断言 | 活真的被干了 | ——这是唯一够格的终点探针（VER-02.4） |

**断言强度不够支撑判据的探针，不许出现在验收判据表里**（ENG-02.3）。
另：护栏与审计工具自身也要有验证——「护栏通过了」与「护栏没执行」
在无验证时不可区分（机理见 DIS-02.4；公开形态见 VER-03 案例 PM-07）。

### VER-01.3　沉默判读：给告警链路装心跳

「没有告警」有两种含义：没有问题，或告警链路死了。区分手段只有一个：
让告警链路**定期发已知信号**（心跳/演练告警），信号停了 = 链路死了。
没有心跳的告警链路，其沉默一律按「未知」处理，不按「正常」处理——
这是保守缺省在观测层的形态。

### VER-01.4　验证资产入库

以上三项的产出（独立性清单、探针语义表、心跳配置）属于交付物清单的
**验证资产类**（ROL-03.1）——它们要随交付移交，否则客户接手的是一批
无人知道断言强度的绿灯。

---

## 常见误判

**「监控没报警，所以没问题」**
先问 VER-01.1 的交集：报警链路和故障共不共享依赖。共享 → 沉默是盲区不是绿灯。
Roblox 的复盘措辞是 "severely hampered"——三天多的处置里有相当部分在跟盲区搏斗。

**「健康检查全绿，所以服务健康」**
回 VER-01.2 的表：每个绿灯只断言它测的那一层。把端口存活读成业务可用，
是把探针的断言强度私自升级——升级的部分没有任何东西背书。

**「状态页/仪表盘是权威」**
状态页也是一个有依赖的系统（AWS SHD 案例）。权威的不是页面，
是页面背后那条链路的独立性——核过才算数。

---

## 判定标准

```checklist
[ ] 验证链路与被验证系统的依赖交集已列出，交集项的「安静」已标注为不可作证
[ ] 每个探针有「实际断言」一行，判据表中无断言强度不足的探针
[ ] 告警链路有心跳，无心跳的链路其沉默按未知处理
[ ] 三项产出已入验证资产清单（ROL-03）
```
