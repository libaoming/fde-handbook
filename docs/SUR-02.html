SUR-02 · 非工程域勘察：不在日志里的阻塞项

目的　把不产生任何技术信号、却能让整条链路停摆的事项，在勘察阶段挖出来、问清周期、登记到人。这类事项的特点：它们不报错、不告警、不出现在任何监控里，且工程努力对它们完全无效——错过勘察窗口后，你只能在停摆中等它。

前置条件 - ROL-02 的边界登记表已建（本节的产出全部登记进去） - 正在做 SUR-01（两节并行，本节专管工程视野之外的那一半）

规程

SUR-02.1　六个必查域

逐域过一遍，每域三问：这次交付碰不碰它？周期多长？谁负责推进？

域 典型事项 特有陷阱
备案与合规 域名备案、算法备案、数据合规评估、行业准入 周期以周/月计且法定，技术手段无法缩短
账号与配额 云账号开通、API 配额、模型服务开通、白名单 「有账号」≠「有这个能力的权限」，逐能力核
授权范围 采购的商品/许可证覆盖哪些能力、并发、环境 销售口径 ≠ 合同条款，以合同为准
合同与计费 付款节点、超量计费、到期日 欠费停服不提前通知的供应商真实存在
数据出域 数据能不能离开客户环境/地域/网络分区 客户 IT 与法务的答案可能不同，两边都要问
印章与流程 验收单、变更单、进场许可需要谁签、走多久 每一道签字都是一段日历时间，计入排期

SUR-02.2　每个命中项登记四字段

命中的事项进 ROL-02.4 边界登记表，四个字段缺一不可：

  • ☐owner：一个名字（部门不算，见 FX-ORG-01）
  • ☐周期：官方/流程口径的时长，问不到就要历史样本（「上次走这个流程花了多久」）
  • ☐证据：完成时会拿到什么可核验的凭证（备案号、开通截图、盖章件）
  • ☐排期位置：它阻塞哪些后续动作——把它画进关键路径，而不是「另一张表」

SUR-02.3　对「等待」的纪律

非工程域事项的正确动作经常是什么都不做地等——而这恰恰是工程师最难执行的动作。两条纪律：

  1. 等待期间不绕道。 绕开审批的临时通道（换域名、借账号、走灰色代理）会活得比它解决的问题更久，并在最坏的时刻被清算（VER-03 的 Rollback 教训同源）；
  2. 等待要有心跳。 每个等待中的事项定一个复查节奏（谁、多久问一次、向谁升级），写进登记表——「在等」和「没人管」的区别只有这一行字。

常见误判

「这些是商务的事，不归我管」分工上也许是，但停摆账单记在交付头上。FDE 对非工程域事项的责任不是去办，是确保每项有人办、周期已知、且在关键路径上可见（ROL-02 的归属三问）。

「技术都通了，剩下的是走流程」「走流程」三个字里藏着以周计的日历时间和随时可能出现的驳回。流程不是尾款，是关键路径上的一段——SUR-02.2 要求把它画进排期，原因在此。

「客户说没问题，就是没问题」问「有没有问题」得到的永远是「没问题」。要按 SUR-02.1 逐域问具体问题：备案办到哪一步了？配额批了多少？合同里写的是哪几个环境？具体的问题才能暴露具体的坑。

判定标准

  • ☐六域逐一过筛，命中项全部四字段登记
  • ☐每个命中项已画入关键路径（它阻塞什么，一眼可见）
  • ☐等待中的事项有心跳（复查节奏 + 升级路径）
  • ☐无任何「应该没问题」状态的项——只有「已核」与「已登记待办」两种

保守缺省：某域「大概率不涉及」但没核过 → 按涉及处理，花五分钟问掉它。这五分钟是全手册性价比最高的五分钟。
